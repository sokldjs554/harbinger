CI·병합·공개 배포는 그 기록의 PR/실행 링크와 최종 인계에서 커밋별로 확인한다.

## 사용자에게 확인된 방향과 검토

사용자가 확인한 프로젝트 방향은 시설 점검 기록에서 우선 확인할 설비를 고르고 원문 근거를 되짚는 흐름이다. 실제 고객 자료를 확보했다거나 현장 수요를 실증했다는 뜻은 아니다. 기존 점검대장 UI를 유지하면서 사용자가 전달한 의견에 따라 위치 검색, 적용 기준일, 현장 판정과 모델 확률의 구분, 미확인 수리 상태, 기록 완전성 확인과 평가 보류를 보완하는 방향을 확인했다.

사용자는 공고 대응에서 **FastAPI·AWS 유지와 TensorFlow 실행 보완**을 선택했고, 기존 기술을 유지하며 필요한 검증을 마무리하도록 요청했다. 메모 재실행·HGB 선택·실제 순찰 평가·집계 보완의 목적과 범위는 사용자 요청에 따른다. 실험 시드·구체적 교체 문턱·검증 구현은 [사전 설계](superpowers/specs/2026-10-26-evaluation-completion.md)에 기록한 구현자의 판단이며, 사용자가 직접 정한 모든 수치라고 쓰지 않는다.

시설관리 동료 A와 일반 사용자 B의 검토 기록은 사용자가 전달했다. 이후 “추가 문제 없음”이라는 정성적 회신도 전달받았다. [사용자 검토 원문과 해석](user-reviews/README.md)을 보존한다. 응답자별 재검토 구분·버전·과업 성공 여부·도움·측정 시간이 없으므로 A/B 각각의 과업별 재시험 완료, 무도움 성공률 개선, 시간 단축을 새로 주장하지 않는다. B의 원래 시간·발언에 남은 불확실성도 소급 해소하지 않는다.

## 설명할 수 있는 기술 판단

메모 누락 반복에서 개선형이 유리하더라도 그 결과를 HGB 기본값 변경의 근거로 옮기지 않았다. HGB는 별도의 미관찰 합성 시드 검증으로 비교하고, 정한 교체 조건에 못 미쳐 전체 모델을 유지했다. 보정과 선택이 같은 검증 기간을 사용한 한계, 테스트의 실행별 반대 결과, 합성 데이터의 한계를 함께 남겼다.

확률이 높은 설비 열 개를 고르는 평가와 중요도·필수 설비를 반영하는 실제 순찰을 분리했다. 필수 수가 요청 K를 넘을 수 있으므로 실제 선택 적중률에 Precision@10라는 이름을 붙이지 않았다. 고객사마다 관측 날짜 수가 다를 때 점 추정과 bootstrap의 가중이 같은지 확인했다. 과거 결과·실패 기록·원시 배열·해시를 보존하며 재실행 결과를 별도 기록했다.

이 판단과 코드를 설명할 때 **Codex의 코드 작성·수정, 실험 실행, 검증 및 문서화 지원을 사용했다**는 역할을 함께 밝힌다. 사용자의 확인된 역할은 문제·제품 방향과 기술 범위의 선택, 검토 의견 전달, 결과 확인과 후속 작업 요청이다. 저장소에 구현과 검증이 존재한다는 사실만으로 사용자가 모든 코드를 혼자 작성했거나 동일 문제를 독립적으로 해결할 수 있다고 단정하지 않는다.

## 추가 확인 없이 쓰지 않을 주장

개인의 학력·졸업 상태·고용 경력·근속 기간·단독 코딩 숙련도는 확인되지 않았다. 시설관리 동료의 경력을 사용자의 경력으로 옮기지 않는다. 합성 실험을 실제 고객 정확도·고장 예방·비용 절감·현장 성과로 환산하지 않는다. 정성적 재검토 회신이나 자동 브라우저 검사를 사람의 과업 재측정 시간으로 바꾸지 않는다.

기존 AWS 배포·TensorFlow 검사·브라우저 검증은 해당 날짜의 [과거 감사 기록](verification/requirements-20261026/README.md)에 따른다. 이번 로컬 번들은 v20261026-093937·특징 v3다. 같은 고정 입력의 동시4 요청에서 각 경로 429는 90%→0%였지만 대기 지연은 늘었다. [전후 원시 근거](verification/completion-20261026/operations/README.md)는 AWS 처리량이 아니다. PR #16은 `e33072b`로 병합됐고 main CI·AWS·Pages가 모두 성공했다. AWS 모델은 `v20261026-151241`, 저장 예제는 `v20261026-093937`, 특징 정의는 3이다. [최종 배포 원본·검사 링크](verification/closeout-20261027/README.md)를 보존했다. 과거 버전을 현재 서비스 버전으로 표기하지 않는다. 동료 A·친구 B의 새 7과업 실제 재검토 기록은 아직 미수신이다. 외부 이메일은 [통제된 네이버 SSL 시험](ops/external-alerts.md)에서 장애·복구 전송과 프로젝트 소유자의 두 메일 실제 수신을 확인했다. 운영자의 표시 시각 회신은 10월 27일 02:58 KST(분 단위)이며, 메일별 구분·메일함 종류·초 단위 전달 지연은 미확인이다.

후속 확인에서 사용자는 GitHub Secret 설정, 네이버 SMTP 사용 설정 저장, 시험 이메일 실제 수신 확인을 맡았다. SMTP 연결 코드·실패 원인 기록 보완·실행·검증·문서화에는 Codex 지원을 사용했다.
