# 모델링 — 무엇을, 왜 이렇게

## 문제의 형태

점검 1건이 학습 행 1개다. 행의 시점 t 에서 질문은 셋이다.

1. **분류**: 이 설비가 30일 안에 비계획 고장을 낼 확률은? → 순찰 우선순위, 즉시 점검 판단
2. **생존**: 고장까지의 시간 분포는? → 권고 점검 주기 ("다음 점검 전에 고장날 확률 ≤ 5 %" 인 최대 간격)
3. **회귀**: 이 건물의 오늘 에너지는 날씨·재실을 감안했을 때 정상인가? → HVAC 효율 저하의 독립 증거, 설비 위험의 피처

세 질문은 같은 피처(`docs/data-model.md`)를 공유하고, 답은 하나의 API 로 나간다.

## 1. 분류기 — HistGradientBoosting + 선택적 보정

- 입력 116열(원-핫 포함), 결측은 그대로(HGB 네이티브). `max_leaf_nodes=15, min_samples_leaf=100, lr=0.04, l2=2.0`, 내부 15 % 조기종료.
- **보정은 검증 기간(시간상 학습 뒤 6개월)에서 고른다.** 순위만 쓰는 모델이라면 필요 없지만, 처방은 확률을 쓴다(기대손실 = P30 × 중요도 가중, 권고 주기 = 위험 예산). 원시 확률·Platt·isotonic 을 **교차적합** 로그손실로 비교해 원시보다 상대 0.5 % 이상 좋아질 때만 채택한다. 이번 번들은 원시 확률이 선택됐다(검증 행으로 적합하고 같은 행으로 평가하면 isotonic 이 늘 이기고, 계단함수가 같은 확률 값을 반복시킨다). 후보별 점수는 `artifacts/metrics.json` 에 남긴다.
- 베이스라인: 연식만 · 마지막 점검만 · 로지스틱(전체 피처) · 상수 사전확률 · **오라클**(숨은 열화 상태로 계산한 진짜 30일 확률 — 합성 데이터에서만 가능한 상한).
- 절제: 체크리스트만 → +메모 → +점검 품질 → +고장 이력 → +에너지. 그리고 전체에서 메모·품질·고장 이력을 각각 뺀 것.

## 2. 생존 — Cox PH · Weibull AFT · 이산시간 위험 네트

점검 행의 대부분은 "아직 고장 안 남"이다. 분류 라벨은 호라이즌 하나(30일)만 보지만 생존 모델은 전체 시간을 쓴다.

- **Cox / AFT (lifelines)**: 표준화·중앙값 대치 후 적합, 패널라이저 0.05. C-index, 추적 기간과 검열 지지 범위 안의 IPCW Brier 및 IBS를 보고한다. 현재 360일 시점은 보류한다. 같은 설비의 행들이 독립이 아니므로 **점추정과 순위 지표만** 쓴다.
- **이산시간 위험 네트 (PyTorch)**: 30일 구간 12개의 조건부 위험 h_k 를 출력한다. 손실은 중도절단을 다루는 이산 NLL:
  사건 구간 k 이면 −log h_k − Σ_{j<k} log(1−h_j), 중도절단이면 −Σ_{j<k} log(1−h_j).
  입력 = 수치 피처 + 카테고리 임베딩(8) + 아키타입 임베딩(4) + **사이트 임베딩(8, 학습 중 30 % 를 '미지 사이트' 로 치환)** + **메모 문자 CNN**(문자 임베딩 32 → 커널 2/3/5 × 48 채널 → max-pool).
  P30 = h_0 이므로 분류기와 같은 잣대로 비교할 수 있고, S(t) 가 나오므로 권고 주기를 선형 보간으로 읽는다.
  사전학습 언어모델을 쓰지 않은 이유: 배포 환경(고객사 내부망·Cloud Run 콜드스타트)에서 모델 다운로드에 의존하지 않기 위해서다. 문자 단위라 오타·축약에 비교적 강하다.
- 변형 3개(메모+사이트 / 메모 없음 / 사이트 없음)를 같은 분할에서 비교해 **메모 인코더와 사이트 임베딩이 각각 무엇을 보태는지** 본다.

## 3. 에너지 회귀 — HGB 회귀 → 잔차 → 이상

- y = 일 전기 kWh, x = 기온·CDD·HDD·재실·요일·계절·사이트(범주). 각 기준 월 이전 자료로 적합하고 학습 cutoff 이후에는 고정한다. 과거가 60일 미만이면 미래 자료를 쓰지 않고 결측 처리한다.
- 잔차 비율의 **7일 이동평균**을 사이트별 학습기간 표준편차로 나눠 z. z > 2.5 를 이상일로 표시한다.
- 검증: 합성 데이터에서는 숨은 냉방설비 열화(사이트 평균 D)와 여름 잔차의 상관, 열화 상위 25 % 를 z 로 맞히는 AUROC 를 본다. 실데이터에서는 서브미터링이 없는 한 설비 단위 증거가 아니라 **군 단위 증거**다.

## 4. 콜드스타트 — 신규 고객사

- 평가: **leave-one-site-out.** 아키타입별 2개 사이트를 보류하고, 나머지로 학습한 pooled 모델로 보류 사이트의 테스트 기간을 예측한다.
- 보정: 보류 사이트의 자체 데이터 m 개월(0/3/6/12)로 경험적 베이즈 로짓 오프셋 δ = n/(n+κ)·(logit 관측률 − logit 예측평균), κ=20 사건.
- 비교선: 그 사이트를 포함해 학습한 warm 모델. 차이가 "자기 데이터가 있을 때 더 얻는 것"이다.

## 5. 처방

- **순찰 우선순위**: score = P30 × 중요도 가중(1 / 1.8 / 3.0). 법정 설비는 기한 3일 전부터 무조건 포함. 선택된 k 개를 지하→고층, 구역 순으로 정렬해 동선으로 낸다.
- **권고 주기**: 생존곡선에서 1−S(Δ) ≤ 위험 예산(5 %) 인 최대 Δ, [7, 90]일로 클립, 법정 상한 적용. 위험 네트가 없으면 P30 을 일정 위험으로 펼쳐 계산.
- **설명**: SHAP(TreeExplainer) 상위 기여 + 그 기여를 만든 **실제 점검 메모 원문**(약·강 수식어 표시), 지적 항목, 최근 이력. 숫자가 아니라 문장으로 보고서에 들어간다.
