# 고객의 기록에 맞춰 모델을 고르는 기준

프로젝트의 기본 모델 선택은 전체 HGB 유지다. 실제 공개 서비스의 소스·모델 버전은 배포 실행 기록으로 별도 확인한다. **검증 자료에서 고객사별 후보를 선택하고 정책을 활성화·롤백하는 기능**을 구현했다. [실행 절차와 시간 경계](site-model-policy.md)를 따르며, 실제 고객별 최적 모델을 입증한 결과는 아니다.

현재 활성화 가능한 정책은 **30일 간격의 같은 기준일·설비에서 상위 10개 적중률과 Brier를 함께 비교**한다. 날짜마다 50개 설비, 4개 기준일/90일 이상을 요구하고 설비·날짜별 재표집의 하한과 각 날짜의 업무 악화를 확인한다. 이 수치는 현장 검증된 표본 수가 아닌 보수적인 자격 제한이다. [고정 계약과 이전 정책 이행](site-model-policy.md), [이번 합성 선택 원시 근거](verification/audit-20261026/policy-report.md)를 참조한다. 선택 자료를 독립 테스트로 재사용하지 않는다.

## 새 검증 자료로 고정한 기본 모델 결정

자료 시드 202610261/262/263 × 학습 시드 17/29, 같은 생성기·36개월·24/6/6 시간 분할에서 전체 특징 116개와 메모 유래 특징을 제외한 84개를 비교했다. 시드와 교체 기준은 결과 확인 전에 고정했다. 과거에 공개한 세계의 테스트나 메모 누락 실험의 성공 여부로 기본값을 선택하지 않았다.

교체하려면 검증 여섯 실행 모두 P@10가 낮아지지 않고 Brier가 높아지지 않아야 하며, 평균 AUROC·PR-AUC도 낮아지지 않고 고객사 블록 paired bootstrap 2,000회의 평균 P@10 차이 하한이 0보다 커야 했다. 메모 제외 후보는 이 조건을 충족하지 못했다. 검증 평균 P@10는 전체 26.5905%, 메모 제외 26.2667%, `메모 제외 − 전체`의 조건부 95% 구간은 −0.7715~+0.1556%p였다.

**전체 HGB 유지 선택과 검증 예측 해시를 저장한 뒤 여섯 테스트를 계산했다.** 테스트 평균은 전체 25.8909%, 메모 제외 25.5212%였으며 첫 세계의 두 실행에서 메모 제외가 더 높았던 결과도 보존했다. 선택이나 문턱을 테스트에 맞춰 바꾸지 않았다. [선택 기준·동결·모든 지표와 반복 편차](verification/completion-20261026/technical-results.md#2-hgb-기본-모델의-새-검증-선택)에 근거가 있다.

검증 기간은 보정에도 사용했으며 독립 테스트가 아니다. 세 세계 안의 두 학습 반복을 독립 고객 여섯 곳으로 세지 않는다. 새 합성 시드에서 전체 모델을 유지할 근거와 실제 고객의 일반화 성능은 구분한다. 원문 메모는 어느 후보를 선택하더라도 기록 확인과 설명을 위해 보존한다. 아래 과거 반복 실험과 현재 [단일 실행 산출물](../artifacts/metrics.json)은 이 선택의 대체 근거가 아니다.

## 평균이 높아도 모든 조건에서 앞서지는 않았습니다

[과거 합성 데이터 안정성 실험](verification/robustness-20261025/README.md)에서 생성 시드 3개와 학습 시드 2개를 조합했다. 6회는 서로 독립적인 고객 6곳이 아니라, 3개 합성 세계 안에서 두 번씩 학습한 결과다. 같은 사이트·날짜·설비에서 주간 상위 10개를 선택했다. 아래 값은 당시 소스의 역사적 결과이며 현재 재학습 표로 갱신하지 않는다. PyTorch는 중복 사이트 마스크의 기대 51%가 적용된 과거 구현이다.

| 확인한 근거 | 선택에 반영할 판단 |
|---|---|
| 전체 HGB의 AUROC 평균 0.7725, 주간 Precision@10 평균 26.33% | 우선 비교할 후보로 유지한다. 실제 고객에서도 같은 성능을 낸다고 가정하지 않는다. |
| 메모 제외 HGB의 주간 Precision@10 평균 26.00%; 실행별로는 6회 중 4회 전체 HGB보다 높음 | 평균 순위만으로 메모 사용을 필수로 정하지 않는다. 고객별 검증에서 두 후보를 함께 비교한다. |
| PyTorch text+site는 메모 25% 누락 시 주간 Precision@10 평균 23.94% → 17.73% | 누락 대응을 검증하기 전에는 메모가 불완전한 고객의 기본 모델로 채택할 근거가 부족하다. |
| 전체 HGB도 메모 50% 누락 시 주간 Precision@10 평균 약 1.04%p 감소 | HGB라는 이유만으로 입력 품질 영향을 무시하지 않는다. 실제 누락 형태를 반영해 비교한다. |
| 네 보정 분할 모두 원시 확률 5회·Platt 1회·isotonic 0회 선택 | 고객마다 보정을 의무 적용하지 않는다. 시간과 설비의 반복을 고려한 검증에서 개선이 확인될 때 선택한다. |

6회 최솟값·최댓값은 신뢰구간이 아니다. 메모 누락 실험의 비율은 특정 고객에게 전환을 권고하는 임계값도 아니다. 현재 자료만으로 “누락률이 몇 %면 모델을 바꾼다”는 운영 규칙을 확정할 수 없다.

## 먼저 같은 문제를 비교할 수 있어야 합니다

1. **판단할 사건을 정한다.** 비계획 고장의 정의, 향후 30일, 실제 사용 가능한 기록 시각, 비교할 날짜·설비, 현장의 점검 예산을 결과를 보기 전에 합의한다. 실험의 상위 10개는 비교 조건이며 모든 고객의 적정 점검 수를 뜻하지 않는다.
2. **정답의 신뢰 범위를 확인한다.** 자료 담당자가 기록 완전성을 확인할 수 없거나 이후 30일이 지나지 않았다면 고장 없음으로 채우지 않는다. 탐색·예측과 성능 평가를 구분하고, 평가할 수 없는 이유를 남긴다. 현재 API의 최소 양성·음성 건수 조건을 통과하는 것만으로 고객별 우열이 충분히 검증되는 것은 아니다.
3. **시간 순서대로 후보를 비교한다.** 전체 HGB·메모 제외 HGB·로지스틱·재현 가능한 현장 정책을 같은 대상과 예산에서 비교한다. 현장 정책 자료가 없으면 프로젝트의 최근 점검 규칙과만 비교했다고 적는다. 아직 사용하지 않은 미래 테스트 구간을 남긴다.
4. **업무 목적과 오차를 함께 본다.** 원시 위험순 선택에는 Precision@k를, 필수 포함·중요도 가중 순찰에는 실제 선택 적중률·선택 수·초과량을 사용하고 놓친 고장과 점검 비용도 확인한다. 주 점검대장의 기본 위험순 목록과 고급 순찰의 선택 정책을 혼동하지 않는다. 확률을 업무 판단에 쓸 경우 Brier·logloss와 보정 상태도 본다. 반복 설비와 겹치는 관측 기간을 반영한 불확실성을 함께 기록한다. 표본이 부족하거나 차이가 불안정하면 우열을 보류한다.
5. **선택과 변경 이유를 남긴다.** 채택 후보·비교 기준·관측 범위·보류 사유를 저장한다. 현장 비용과 운영 복잡도를 포함해 사전에 합의한 개선 기준을 충족할 때 변경한다. 구현한 정책은 검증 근거·모델/자료 해시를 확인한 뒤 활성화하며, 이후 요청을 해당 고객사의 선택 모델로 계산한다. 과거 날짜로 소급하지 않고 정책이 무효이면 기본 모델과 사유를 반환한다.

## 화면 의견은 무엇을 바꾸었는지도 구분했습니다

[사용자 검토](user-reviews/README.md)는 위치 검색, 과거 예측 날짜, 적용 대기 상태, 한국어 오류, 기록 완전성 확인 절차를 바꾸는 근거가 됐다. 이후 사용자가 추가 문제가 없다는 회신을 전달했다. 과업별 재측정 자료는 받지 않았으며, 사용성 회신으로 예측 모델의 성능 우열을 정하지 않는다.

반대로 합성 모델 성능이 높다는 이유로 화면을 이해하기 쉽다고 판단하지 않는다. **사용자 의견은 작업 흐름을, 평가 결과는 모델 선택을 검토하는 근거**로 연결한다.

## 과거 누락 대응과 수정 후 반복

[2026-10-25의 과거 후속 실험](verification/memo-20261025/README.md)에서 누락 표시·문자 CNN 게이트·학습 중 메모 dropout을 구현하고 새 합성 세계 3개 × 학습 시드 2개로 검증했다. 25% 누락에서 기존 PyTorch 17.64%, 개선형 22.90%, 메모 미사용 모델 23.73%였다. 검증에서는 메모 미사용 5회·기존 유지 1회를 선택했고 고정한 선택의 최종 테스트 채택 기준을 통과했다. 개선형을 일괄 채택하는 근거로 해석하지 않는다.

중복 사이트 마스크와 특징 정의를 수정한 뒤에는 동일한 알려진 세계를 다시 실행했다. 한 번의 epoch별 30% 사이트 마스크와 특징 v3를 사용한 재실행에서 선택 정책의 25/50% 누락 평균 향상은 legacy 대비 +5.100%p, 정상 입력 변화는 +0.139%p였고 원래 판정을 다시 통과했다. [수정 후 보고서·원시 비교](verification/completion-20261026/memo/README.md)는 후향적 반복이며 새 독립 성능 입증으로 부르지 않는다.

추가로 필요한 것은 실제 기록의 누락 형태에서 재검증하는 일이다. 확장 합성 검사에서도 군집 누락·치환·축약·지연을 비교했지만 고객별 누락률 임계값을 확정할 수 없다. 공개 HGB와 기본 PyTorch 모델은 자동 교체하지 않았다.

실제 고객 자료를 확보하면 [실데이터 적용 계획](real-data-checklist.md)에 따라 비교한다. 현재 업로드 데모는 합성 학습 모델의 탐색적 적용이며, 고객별 재학습이나 실제 고객 PoC를 완료한 서비스는 아니다. 정책 선택·추론·롤백은 합성 자료에서 검증했다.
