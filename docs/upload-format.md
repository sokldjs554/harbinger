# CSV 기록 형식 v1

`GET /v1/workbench/example.csv?site=S01`에서 합성 예제를 다운로드한 뒤, 같은 형식으로 업로드할 수 있다. UTF-8 또는 UTF-8 BOM, 쉼표 구분 CSV만 허용한다. 압축 파일·Excel·JSON·모델 파일은 받지 않는다. 필수 열 헤더는 빈 값이 허용되는 열도 포함해야 한다.

| 열 | 제약 |
|---|---|
| record_id | 전체 파일에서 고유한 기록 ID |
| record_type | inspection / breakdown / preventive / parts |
| site_id, asset_id | 영문·숫자·밑줄·점·하이픈, 1~80자. asset_id는 고객사 전체에서 고유 |
| category | chiller, ahu, pump, boiler, elevator, generator, switchgear, fire_pump, cooling_tower, exhaust_fan, auto_door, water_tank |
| archetype | gov_office / hospital / hotel / office |
| installed | 설치 날짜, 기록 날짜보다 늦을 수 없음 |
| criticality, floor, zone | 중요도 정수 1~3, 층 정수 -20~200, 비어 있지 않은 구역 |
| occurred_at | 기록 시각. YYYY-MM-DD 또는 시간대 없는 ISO 시각. 2000~2099년 |
| inspector_id | 점검 행에 필수, ID 문자 규칙 동일 |
| overall | 점검 행에 필수, 0 양호 / 1 주의 / 2 불량 |
| memo | 원문 메모, 빈 문자열 허용, 최대 2,000자 |
| dwell_seconds | 점검 행에 필수, 정수 0~86,400초 |
| scheduled_at | 점검 행에 필수, 예정 시각 |
| method | 점검 행에 필수, nfc / beacon / manual |
| photo_count | 점검 행에 필수, 정수 0~100 |
| chk_* | 선택 열. 스키마의 점검 항목만 허용, 빈 값 또는 0/1/2 |

최대 5 MiB, 20,000행, 500설비, 10고객사, 5년 관측 기간. 파일에 점검이 하나 이상 있어야 한다. 설비 정적 정보가 행마다 다르거나 고객사 유형이 일관되지 않으면 거절한다. 날짜 오류, 필수 값 누락, 동일 설비/기록종류/시각 중복, 중복 ID/열, 지원하지 않는 열/분류를 자동으로 고치지 않는다.

관측 종료일은 사용자가 선언한다. 날짜만 주면 그날 23:59:59까지 관측한 것으로 해석한다. 모든 기록은 같은 현장 시간대를 사용해야 한다. 기록이 없다는 사실만으로 실제 고장이 없었다고 보장할 수 없으므로 사용자는 종료일까지 모든 고장 기록을 포함해야 한다. 이후 30일 관측 미완료, 모델 시간 보류 미충족, 양성/음성 각각 3개 미만은 지표를 보류한다.

서버는 업로드를 별도 세션에서 메모리로 처리한다. 세션 ID는 추측하기 어려운 토큰이며 최대 8개, 생성 후 30분에 만료된다. 만료 자료는 다음 접근 또는 최대 60초 주기의 정리에서 제거한다. 세션 닫기를 누르면 즉시 제거한다. 단일 서버 프로세스로 실행한다. 업로드 내용은 로그/디스크에 저장하지 않는다. 서버 재시작 시 사라진다. 인증과 영속 저장은 지원하지 않으므로 실제 개인정보나 고객 기밀을 공개 데모에 올리지 않는다.

합성 학습 모델을 적용하고 에너지 피처는 결측으로 둔다. 업로드에서 새 모델을 학습하지 않으며, 실제 고객 실증 완료나 분포 적합성을 보증하지 않는다. 결과 CSV는 스프레드시트 수식 시작 문자를 이스케이프한다. 웹의 원문은 HTML로 실행하지 않는다.
