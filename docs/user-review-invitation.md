# 지인에게 보내는 검토 요청

아래 문장을 복사해 전달하세요. 처음에는 영상을 보여주거나 버튼 위치를 알려주지 않고, 도움을 줬다면 그 내용을 기록합니다.

> 내가 만든 시설 점검 기록 분석 데모를 15~20분 정도 직접 사용해 줄 수 있을까? 잘 만들었다는 평가보다, 설명 없이 어디까지 할 수 있는지와 헷갈린 부분을 알고 싶어.
>
> https://sokldjs554.github.io/harbinger/live.html
>
> 1. 목록에서 설비 하나를 찾아 줘.
> 2. 점검 원문과 날짜를 확인하고, 원문과 모델 판단이 어떻게 다른지 네 말로 설명해 줘.
> 3. 고객사나 기준일을 바꿔 계산해 줘. 지금 어떤 조건이 적용됐는지 알려 줘.
> 4. 화면에서 제공하는 합성 예제 CSV를 받아서 다시 업로드해 줘. 자료 확인 기준일은 예제를 연 직후 화면에 채워진 날짜로 진행자가 확인해서 알려 줄게.
> 5. 결과를 내려받고, 어떤 기준일과 조건의 결과인지 찾아 줘.
>
> 각 단계에서 혼자 완료했는지, 도움이 필요했는지, 가장 막혔던 부분과 바꾸고 싶은 한 가지를 알려 줘. 회사 자료나 개인정보는 업로드하지 말아 줘. 언제든 중단해도 돼.
>
> 의견을 메모하고, 네가 허락한 부분만 익명으로 포트폴리오에 사용해도 될까? 화면·음성 녹음은 별도로 동의를 받을게.

진행자는 [기록 양식](user-review-template.md)에 실제 행동·참가자의 말·제공한 도움·소요 시간을 남깁니다. 측정하지 않은 값은 미측정으로 둡니다. 정상 업로드 후 오류 파일의 안내와 기존 결과 유지까지 확인하려면 [전체 7개 과업 절차](user-review.md)를 사용합니다.

사용성 검토는 지금 진행하고, 모델 평가 안정성 검사는 병행합니다. 의견이 도착하면 화면의 실제 문제를 수정·재검토하고, 실험 결과와 함께 고객별 모델 선택 근거를 정리합니다. 친구의 긍정적 의견은 고객 맞춤 모델 성능이나 현장 실증의 증거가 아닙니다.
