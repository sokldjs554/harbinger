# 합성 데이터 생성 모델 — 전부 공개

실제 고객 데이터는 없다. 그래서 **결과 숫자는 이 생성 모델 아래에서의 값**이고, 이 문서는 그 모델을 숨기지 않기 위해 있다.
생성기가 가정한 것이 틀리면 결과도 틀린다. 가장 의심해야 할 가정은 §4 에 따로 적었다. 코드: `src/harbinger/synth/`.

## 1. 세계

| 아키타입 | 사이트 수 | 설비 수 | 점검자 | 재실 패턴 | 부하 | 점검자 성실도 Beta | 복붙 성향 Beta |
|---|---:|---:|---:|---|---:|---|---|
| 정부청사 | 8 | 60~120 | 4~8 | 평일 | 1.00 | (5, 2) | (1, 9) |
| 병원 | 3 | 120~200 | 6~10 | 상시 | 1.35 | (4, 2) | (1, 7) |
| 호텔 | 4 | 80~150 | 3~6 | 성수기·주말 | 1.15 | (3, 2) | (1.5, 5) |
| 오피스 | 10 | 40~90 | 2~4 | 평일 | 0.90 | (2.5, 2) | (2, 4) |

25개 사이트, 2,300여 설비, 36개월(2023-01 ~ 2025-12). 설비 12종의 비중은 아키타입별로 다르다(병원은 발전기·펌프·자동문이 많다).

## 2. 숨은 열화와 고장

설비마다 숨은 열화 상태 D(t) ≥ 0 이 있다.

```
D(t+1) = D(t) + Gamma( mean = RATE_SCALE · rate_c · (1 + age_coef_c · age) · load_site · season_c(t),  scale = 0.02 )
h(t)   = HAZARD_SCALE · h0_c · exp( BETA_SCALE · beta_c · D(t) ) + SHOCK          (일 단위 고장 위험)
```

- `season_c`: 여름 부하 설비(냉동기·공조기·냉각탑·수배전반)는 CDD, 겨울 부하(보일러)는 HDD 에 따라 최대 2.2배.
- `SHOCK = 1.2e-4/일`: 열화와 무관한 돌발 고장. **완벽한 예측이 불가능하게** 만드는 항.
- 고장 → 고장수리 WO, 다운타임·비용은 카테고리별 로그정규, `D ← D·U(0.15, 0.5)` (불완전 수리).
- 연 1회 예방정비 → `D ← D·U(0.10, 0.35)`. 점검 불량 → 85 % 확률로 1~5일 뒤 부품교체 WO → `D ← D·U(0.2, 0.5)`. 점검 주의 → 20 % 확률로 예방정비.
- 전역 배율 `RATE_SCALE=0.70, HAZARD_SCALE=0.22, BETA_SCALE=1.40` 은 (a) 양호 판정 80 %대 (b) 설비당 연 0.6~0.9건 고장 (c) 열화-주도적 고장이 되도록 맞춘 값이다.
  BETA_SCALE 을 올린 이유: 처음 설정(β≈2.3)에서는 숨은 상태를 **그대로 아는 오라클조차 AUROC 0.74** 였다. 그 세계에서는 어떤 모델도 차이를 보여 줄 수 없다.
  1.4배로 올리면 오라클이 0.8 초반이 된다. 실제 기계 설비의 고장이 대체로 열화-주도적이라는 가정에 기댄 선택이고, **이 선택이 결과 숫자를 좋게 만든다**는 점을 명시한다.

## 3. 사람의 관측

점검 주기는 카테고리별 14/21/30일(±2일) + 점검자 지연(기하분포, 성향이 높을수록 자주·길게; 법정 설비는 31일 넘지 않게).

항목별 관측(임계 θ1, θ2 는 카테고리·항목별, 관측 시 `OBS_SHIFT=(0.70, 0.80)` 을 더한다):

```
P(주의) = σ((D − θ1)/0.15) · (0.45 + 0.55·성실도)
P(불량) = σ((D − θ2)/0.12) · (0.55 + 0.45·성실도)
```

- **복붙 점검자**(확률 = 점검자의 복붙 성향): 전부 양호, 이전 메모 복사(70 %) 또는 "ㅇ"·"양호"류, 체류 3~25초. D 가 아주 높으면(θ2+0.3) 50 % 확률로 그래도 불량을 적는다.
- **약신호**: 항목이 양호로 판정됐지만 `θ1 − 0.40 ≤ D < θ1 + 0.05` 이면, 성실도에 비례한 확률(0.35 + 0.55·성실도)로 메모에 약신호 문장("약간의 소음 감지", "미세 진동", "누유 흔적 소량")이 들어간다.
- 메모 길이는 성실도에 따라 1~3문장. 잡일("필터 청소 실시")과 상투어("특이사항 없음")가 섞인다. 템플릿은 `synth/memos.py` 에 전부 있다.

> 이것이 이 프로젝트의 **핵심 가정**이다: *성실한 점검자는 체크리스트가 넘어가기 전에 메모에 먼저 쓴다.* 실데이터에서 이 가정이 약하면 텍스트 피처의 기여는 여기 수치보다 작을 것이다.

## 4. 에너지

```
전기 = 기준부하 · (0.5 + 0.5·재실) · (1 + 0.03·CDD·(1 + 1.2·냉방설비 평균 D) + 0.006·HDD) · (1 + N(0, 0.03))
가스 = 기준     · (0.25 + 0.06·HDD·(1 + 0.8·보일러 평균 D)) · (0.6 + 0.4·재실) · (1 + N(0, 0.05))
```

기온은 서울형 사인 곡선 + AR(1) 잡음, 재실은 요일·공휴일(설·추석 포함)·아키타입 패턴. 열화된 냉방 설비는 더운 날 전기를 더 쓴다 — 그래서 사이트 전기 잔차가 HVAC 설비 위험의 독립 증거가 된다.

## 5. 가장 의심해야 할 가정 (실데이터로 가장 먼저 확인할 것)

1. **메모가 체크리스트보다 먼저 움직인다** (§3). 아니라면 `+text` 의 상승폭은 줄어든다.
2. **고장이 열화-주도적이다** (BETA_SCALE). 돌발 고장 비중이 크면 모든 모델의 상한이 내려간다.
3. **점검 불량 → 수일 내 조치**. 조치가 느린 현장이면 "불량 판정"이 더 강한 고장 예측 신호가 된다(여기서는 조치 때문에 약하다).
4. **에너지 효과 크기** (§4 의 1.2). 실제 냉동기 효율 저하가 전기에 미치는 영향은 설비 구성에 따라 크게 다르다.
5. 점검자 성향이 Beta 분포로 **사이트 안에서 섞여 있다**. 실제로는 팀 단위로 균질할 수 있다 → 품질 피처의 분별력이 달라진다.

## 6. 재현

```bash
harbinger synth --out data --seed 20260101          # 약 45초, 4 vCPU
python scripts/synth_stats.py data                   # 분포 확인
```

`data/meta.json` 에 seed·기간·행 수가 남는다. 같은 seed 면 바이트 단위로 같은 parquet 가 나온다(`tests/test_synth.py`).
