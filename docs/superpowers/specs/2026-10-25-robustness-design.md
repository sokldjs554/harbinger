# 합성 평가 안정성과 보정 검증

사용자는 생성/학습 시드, 메모 누락·오타·기록 지연, 반복 설비·겹친 결과 기간의 보정 검증을 요청했다. 사용성 검토는 지인과 병행하고 최종 고객별 모델 선택 해석은 두 근거를 모아 정리한다. 새 고객 성능이나 사용성 결과를 만들지 않는다.

구현 판단: 기존 Python 모델/특징 생성기를 호출하는 별도 오프라인 실험으로 진행한다. 운영 보정법을 즉시 바꾸는 접근은 아직 결과가 없고 사용성 검토 대상의 버전을 바꾸므로 채택하지 않는다. 기존 전체 평가를 반복하는 접근은 에너지·생존 전부를 매번 학습해 요청한 비교의 비용이 커지므로, 대표 HGB/로지스틱/PyTorch text+site와 메모 제거 HGB 및 최근 판정 규칙을 비교한다. 모든 변경은 scripts/robustness와 테스트·실험 문서에 한정한다.

사전 고정: 생성 시드 20260101/20260102/20260103, 학습 시드 17/29, scale=1, 36개월, 24/6/6개월 시간 분할. HGB 기존 기본값, PyTorch 40 epoch 상한과 기존 patience=6. 대표 기존 단일 시드 실험과 다른 학습 시드이며 별도 결과로 보고한다. 하이퍼파라미터를 최종 테스트로 조정하지 않는다.

메모 스트레스는 테스트 구간에만 누락 25/50%, 비공백 문자 삭제 10/30%를 고정 난수로 적용한다. 삭제는 일반적인 오타 전체가 아닌 제한된 문자 누락 모사다. 원문으로 파생되는 모든 이력·품질 특징을 재계산한다. 에너지는 변경하지 않으므로 원본 특징을 ID로 복원한다. 학습/검증 원문·특징은 변화가 없어야 한다.

기록 지연은 모든 점검 기록이 3/7일 늦게 보이는 조건이다. 고장·정비 기록은 즉시 도착한다고 가정한다. 같은 월요일 결정 시각에서 당시 도착한 마지막 점검 특징만 사용하고 기존 Refresher로 시간/고장 이력을 갱신한다. 정답은 원래 사건 시각과 결정 시각으로 독립 생성하며 지연된 점검 시각으로 바꾸지 않는다. 조건 간 공통 설비 집합으로 비교하고 제외·coverage를 기록한다. 메모 손상도 같은 주간 결정 표에서 함께 비교한다.

보정: 기존 row-random 5-fold, asset-group 5-fold, 30일 결과 창 purge를 적용한 expanding calendar time block, 여기에 검증 설비와 보정 학습 설비를 분리한 방식의 OOF를 비교한다. 동일한 공통 검증 행 집합에서 raw/Platt/isotonic 로그손실로 0.5% 이상 개선하는 방법만 선택한다. 각 방법의 후보는 동일 검증 분모, 단일 클래스/빈 fold는 보류한다. 선택 후 전체 성숙 검증 자료로 재적합하여 고정 테스트로 1회 평가한다. group+time 방식은 신규 설비 보정 이전 가능성을 검사하며 모든 운영 상황에 우월하다고 전제하지 않는다. 행 식별자와 실제 fold membership을 저장한다.

지표: AUROC/PR-AUC/Brier/ECE/logloss, 사이트/설비종류별 결과, 주간 사이트별 Precision@10과 paired site-cluster bootstrap 2,000회, 모델 순위 변동. 6회 반복은 독립 6개 데이터셋으로 취급하지 않는다. 스트레스 수준은 실제 현장 발생률이 아니라 민감도 시험이다.

검증: deterministic perturbations, 미래 원문 변경이 과거 특징에 미치는 영향 없음, ID alignment, 지연 가용 시각/정답 불변, 보정 fold의 설비 배제·30일 purge·실제 공통 분모, 단일 클래스 보류, test labels not used for selection. 소스/원자료/예측/분할 해시와 환경을 남긴다. 원시 예측·분할 압축 CSV와 재현 명령, 결과 JSON/요약을 보존한다. 공개 AWS·기존 결과·모델은 교체하지 않는다.
