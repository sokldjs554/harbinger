# 두 검토에서 드러난 혼란을 줄이는 화면 개선

사용자가 전달한 동료 A와 비전공자 B의 검토에 따라 기존 점검대장 흐름을 보완한다. 2026-10-25 대화에서 개선표를 제시했고 사용자가 다음 단계 실행을 요청했다.

- 층·구역·설비 ID를 목록과 상세에 표시하고 검색에 포함한다. API 원본 등록 정보를 사용한다. 과거 저장 예제에는 저장된 상세 근거에서 확인되는 위치만 사용하고 나머지는 미제공으로 표시한다.
- 예측 기준일을 목록·상세·과거 검증 상단에 표시한다. 현장 판정은 점검 당시 상태, 예측은 이후 30일 추정임을 설명한다. 현재 수리 상태는 자료에 없어 미확인으로 표시한다.
- 목록의 기준일 변경과 보고서 조건 변경은 아직 적용되지 않았음을 알린다. 보고서 계산 성공 전에는 기존 결과·내보내기 조건을 보존한다.
- 업로드의 기록 완전성 확인은 선택으로 바꾼다. 미확인 시에도 탐색적 예측을 제공하되 이후 고장 결과·성능·고객별 평가를 서버에서 보류한다. API 기본값도 미확인이다. 확인 여부는 세션마다 독립적이며 재업로드가 필요하다.
- CSV 숫자 오류에 한국어 항목명, 허용값, 헤더 포함 CSV 행 번호를 제공한다.
- 기존 합성 모델, 점검대장 구성, 필터·초점·스크롤 복원은 유지한다. 모델 재학습, PDF, 작업 지시·담당자 관리, 확인되지 않은 사용자 재검토 결과는 범위에 넣지 않는다.

## 접근 방식
문구만 바꾸면 위치 검색과 미확인 업로드를 해결하지 못한다. 전체 화면 재설계는 기존 사용 흐름을 불필요하게 바꾼다. 따라서 기존 구조에서 API 계약과 필요한 화면 동작을 함께 수정한다. 이 구현 선택은 작업자가 정했다.

## 검토 기록
A 원문은 별도 기록으로 보존하고 빈 양식을 복구한다. B는 제공된 답변·시간·도움 여부를 보존하되 예시/추가 확인이라는 상충 표현을 삭제해 실측으로 둔갑시키지 않는다. 사용자가 실제 친구 검토로 전달했다는 설명과 미확인 항목을 함께 기록한다. 두 사람의 검토는 실제 고객 성능 실증이 아니다.
