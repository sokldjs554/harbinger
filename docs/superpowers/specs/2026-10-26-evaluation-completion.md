# 평가·처리량·제출 마무리 설계

기준은 PR #16 최종 `5a7f947146dd24b43eb79a8e4744449615dabc17`. 사용자 지시의 여섯 항목만 구현한다. 기술 보완 1~4 → 운영 검토 5 → 제출/병합/기존 AWS·Pages 배포 6 순서다. 새 유료 리소스·공개 부하·새 기술·화면 재설계는 제외한다. 이미 사용자에게 실행·병합·배포를 승인받았으므로 설계 승인을 다시 요구하지 않는다. 아래 수치 선택은 구현자의 사전 판단이며 사용자가 정한 값인 것처럼 표현하지 않는다.

## 1. 수정 후 메모 재실행

기존 계약 `2026-10-25-memo-design.md`를 그대로 사용: 자료 시드 202610251/252/253 × 학습 17/29, scale1, 36개월,24/6/6,40epoch,patience6,lr.002,batch1024. clean/25/50/100% 누락. legacy/robust/no_memo, 기존 검증 선택·보고 기준을 변경하지 않는다. 소스는 수정된 PR16 기준 커밋으로 고정한 별도 체크아웃에서 실행한다. 과거 세계의 반복 실행이므로 새 독립 성능 입증으로 부르지 않는다. 기존 메모 실험은 선택 수 합계 비율과 같은 비율을 bootstrap에서 재계산하므로 task4의 서로 다른 추정대상 문제와 구분한다.

## 2. HGB 기본 모델 선택

이미 공개된 seed20260101 및 위 과거 3세계의 테스트로 선택하지 않는다. 새로 고정한 자료 시드 **202610261/262/263**, 학습 시드 **17/29**, scale1,36개월,24/6/6, 같은 HGB 설정·보정 규칙. 전체와 `model_columns`의 메모 유래 특징 제외를 비교한다. 새로운 외부 고객 자료가 아닌 같은 생성기의 미관찰 시드다.

선택 입력은 세 세계의 검증 구간뿐이다. 6실행 모두에서 clean Precision@10 차이 >=0, Brier 차이 <=0를 요구하고, 6실행 평균 AUROC/PR-AUC가 악화되지 않아야 한다. 추가로 고객사 시계열 전체를 유지해 재표집한 paired site-cluster bootstrap(2000회,seed20261026)의 세계·학습 실행 동일 가중 평균 Precision@10 차이 하한 >0을 요구한다. 성숙 주간 날짜·같은 설비·K10을 사용한다. 목표는 제한된 점검 예산의 개선이며 Brier/판별 지표는 악화 방지다. 근거 부족/조건 미달이면 전체 모델 유지. 문턱은 결과를 본 뒤 변경하지 않는다.

검증 선택 JSON과 검증 예측 해시를 먼저 저장하고, 그 후 새 세계의 테스트 예측을 계산한다. 테스트 실패는 보고하며 선택을 바꾸거나 조정하지 않는다. 선택 규칙은 성능/불확실성 근거가 부족하면 기본 전체 모델을 유지하는 보수적 교체 규칙이다. 만약 교체되면 서비스 학습 기본값·메타데이터·설명/비교 이름을 함께 변경한다. 원문은 어떤 모델 선택에서도 기록 확인용으로 보존한다.

## 3~4. 실제 선택과 같은 가중 평가

위험 순위 K10과 `rank_patrol`이 적용하는 중요도(1/1.8/3)·필수 포함 조건을 분리해 보고한다. 서비스의 실제 선택 코드를 공동 사용하고 평가에서 별도 복제하지 않는다. 비교 방식은 같은 대상/날짜/요청 K/필수 설비를 공유하며 규칙 점수는 각 규칙의 우선순위를 유지한다. 후보 모델의 서비스 점수에는 같은 중요도 가중을 적용한다. 필수 수>K이면 모두 포함하고 실제 선택 수·필수 수·초과량·적중 수를 보존한다. 이 적중률을 Precision@10이라고 부르지 않는다.

주 순찰 지표는 고객사 동일 가중: 각 고객사 내 관측 날짜별 비율 평균 → 고객사 평균. 고객사 bootstrap도 같은 고객사 평균을 재표집한다. 같은 설비/겹치는 기간은 고객사 블록 안에 유지한다. 비교는 공통 고객사·날짜를 요구하며 빈/불완전/한 고객사 자료는 해당 불확실성 보류로 명시한다. 과거 날짜 가중 결과는 별도 수치로 남긴다. 불균등 날짜 fixture와 기존 균등 자료의 일치/차이를 검사한다. 메모 누락 반복 실험의 기존 합계 비율 계약은 소급 변경하지 않는다.

## 5. 처리량

기술 보완·모델 선택 완료 후 동일 모델/입력/호스트/스레드/요청 수로 수정 전후 로컬 API 비교. 기존 2개 계산 슬롯을 단순 해제하지 않는다. 즉시 거절 정책인지 실제 CPU/RSS/처리시간 포화인지 구분한다. 필요하면 유한 대기 수·시간을 갖는 제한된 대기로 짧은 burst를 흡수하며 한도를 넘는 요청은 429+재시도 안내로 거절한다. 기존 1/4 동시·각20요청을 유지하고 초과 대기/시간초과 시험을 추가한다. 분석·업로드·다운로드, 성공/429/서버실패/지연/CPU/RSS/회복을 원시 기록한다. 공개 AWS 부하 시험은 하지 않는다.

## 6. 제출·배포

과거 산출물을 보존하고 현재 재학습/선택/서비스 평가/운영 결과를 별도 버전으로 기록한다. 개인 역할은 사용자가 직접 확인한 요구·설계 선택/검토와 Codex가 작성·실행한 코드/실험을 구분하며 개인 숙련도·경력을 만들지 않는다. 전체 검사·TF·API·브라우저·모바일·Docker·CI 후 PR16에 후속 커밋을 통합·병합한다. 기존 AWS 인스턴스만 사용하고 main의 CI 통과를 기다리는 기존 배포 흐름을 유지한다. 소스/모델/특징 버전·CSV/다운로드·공개 화면을 확인하고 결과 및 미완료 항목을 링크한다.
