# 수정한 화면을 다시 확인합니다

준비 기준: 2026-10-27 KST. **아래는 안내와 빈 양식이며 재검토 완료 기록이 아니다.** [동료 A 기록지](retest-20261027/colleague-a.md)와 [친구 B 기록지](retest-20261027/friend-b.md)를 각각 사용한다. 기존 기록과 “추가 문제 없음” 회신은 수정하지 않는다.

## 시작 전 버전과 자료 고정

| 모드 | PR #16 배포에서 확인한 기준 | 허용 과업 |
|---|---|---|
| AWS 실제 계산 | 소스 `e33072bc88652dc8e4bc50f9e3c68b9d44966379`, 모델 `v20261026-151241`, 특징 정의 3 | 7개 전체 |
| Pages 저장 결과 재생 | 배포 소스 `e33072bc88652dc8e4bc50f9e3c68b9d44966379`, 모델 `v20261026-093937` | 탐색·저장 결과 다운로드; 업로드·새 계산은 미실시 |

진행자는 당일 `/deployment.json`, `/version`, 화면의 실제/저장 모드를 다시 확인하고 **실제로 보인 값**을 기록한다. 이 표는 예상 기준이며 당일 관측값을 대신하지 않는다. 버전이 달라졌다면 기록을 분리하고, 확인할 수 없으면 `미확인`으로 남긴다. 저장 예제에서 임의 날짜의 새 계산을 수행했다고 적지 않는다.

정상 예제 CSV와 복사한 오류 CSV(헤더 포함 13행 `overall=9`)를 준비하고, 파일 SHA-256·실제 변경 행·관측 종료일을 기록한다. 13행이 없는 자료라면 실제 변경 행을 기록하며, 정상 파일은 그대로 보존한다. A/B에게 같은 과업과 자료 조건을 제공하되 다른 참가자의 답을 알려주지 않는다. 참가자에게는 기존 [7개 과업 문장](../user-review.md)을 그대로 읽고 버튼 위치·정답은 먼저 설명하지 않는다.

날짜·시각은 `YYYY-MM-DD HH:mm:ss +09:00`으로 적고, 기록 도구의 버전 필드에 `소스 SHA / 모델 ID / 특징 정의`를 함께 넣는다. 진행자·참가자·모드·브라우저·자료 해시는 양식에도 남긴다. 재시도는 기존 결과를 덮어쓰지 말고 별도 회차로 기록한다.

[진행자 기록지 열기](https://sokldjs554.github.io/harbinger/retest.html) · [실제 계산 데모](https://sokldjs554.github.io/harbinger/live.html)

참가자는 데모를 사용하고 진행자는 기록지를 별도 탭에서 엽니다. 공개 페이지의 기록지에도 관찰 결과는 서버로 전송되지 않습니다. 별칭·버전·실행 환경·자료 조건·이전 사용 경험을 입력한 뒤, 같은 7개 과업을 순서대로 진행합니다. CSV 과업은 실제 계산 환경에서만 수행합니다.

1. 시작 버튼을 누른 뒤 과업을 설명합니다. 화면 위치나 정답을 먼저 알려주지 않습니다.
2. 서버를 기다릴 때는 ‘대기’, 설명·휴식에는 ‘중단’, 다시 조작할 때는 ‘조작 재개’를 누릅니다. 다른 탭으로 옮겨도 시계는 계속 갑니다. 컴퓨터 절전·시계 동작이 의심스러운 기록은 측정 근거로 사용하지 않습니다.
3. 도움을 줬다면 내용을 남기고 ‘도움 후 완료’를 선택합니다. 완료하지 못하면 막힌 지점을 적습니다. 하지 않은 과업은 ‘미실시’로 기록합니다.
4. 마지막에 JSON을 내려받습니다. 기록은 자동 저장되지 않으며, 현재 도구는 완료·미실시로 정리한 7과업을 한 파일로 저장합니다. 다시 시도하는 경우 새 기록으로 남기고 이전 기록도 보존합니다.
5. 공개 인용은 기록 동의와 별도로 확인합니다. 회사명·직원 이름·연락처·실제 점검 원문은 입력하지 않습니다.

대기는 진행자가 표시한 구간입니다. 실제 API 응답시간과 같다고 주장하지 않습니다. 파일 형식 검증은 사건 순서와 시간 합계·도움 여부의 모순을 검사할 뿐, 관찰자의 진술이나 파일 진위를 독립적으로 인증하지 않습니다.

## 기록을 확인하려면

```bash
python -m scripts.retest_records after.json
# 같은 참가자·환경·과업/자료 조건의 전후 기록이 실제로 있을 때만
python -m scripts.retest_records before.json --after after.json
```

이 비교는 실제 관찰 기록만 허용합니다. 자동 검사 파일은 `record_kind=tool-test`로 표시되고 사람의 비교에서 제외됩니다. 미실시·미완료 과업의 시간을 성공 과업 시간으로 비교하지 않습니다. 같은 사람의 재검토는 학습 효과와 진행 순서의 영향을 받으므로 일반 사용자 전체나 UI 변경의 인과 효과로 확대하지 않습니다.

현재 전달받은 ‘추가 문제 없음’ 회신은 그대로 보존합니다. 새 도구로 측정한 사람의 기록은 아직 받지 않았습니다. 이전 시간·발언을 소급 생성하지 않으며, 이번 도구의 자동 브라우저 시험은 사용자 재측정 완료를 뜻하지 않습니다.

## 실제 회신 후 반영 순서

1. 참가자별 원본 JSON/메모를 보존하고 날짜·버전·모드·동의·7과업 결과·도움·시간의 누락을 확인한다. 빈 기록지는 완료 기록으로 가져오지 않는다.
2. JSON은 위 검증 명령으로 확인한다. 수동 기록은 누락된 값을 추정하지 않으며, 측정되지 않은 시간은 `미측정`으로 남긴다. 미실시 과업의 시간은 0초의 성공 사례가 아니다.
3. 총 경과시간 = 조작시간 + 시스템 대기시간 + 진행자 설명/휴식 중단시간으로 구분한다. 기록 도구의 대기는 진행자가 표시한 관측 구간이며 서버 측 지연 계측과 같지 않다.
4. 참가자 진술·관찰 행동·진행자 해석을 구분하고, 인용 공개 동의 범위에서만 최종 문서에 옮긴다.
5. 과거와 참가자·모드·과업·자료·시간 측정 방식이 맞는 경우에만 쌍으로 비교한다. B의 과거 시간은 실측 여부가 불명확하므로 새 기록이 와도 자동으로 개선율을 계산하지 않는다. A의 과거 버전·측정 정의도 일치 여부를 확인해야 한다. 반복 사용의 학습 효과를 UI 개선의 인과 효과로 표현하지 않는다.
