기준 소스: `a24fd1d1f1f83bc48b47bbe8b27bbc51bbe0fcc7`. 아래는 코드 수정의 검증 기록이며 실제 고객 실증 기록이 아닙니다.

## 재현한 문제와 수정

| 문제 | 수정 전 재현 | 수정과 회귀 검사 |
|---|---|---|
| 같은 순간을 다른 문자열로 적은 CSV | 날짜/날짜시각, T/공백, 초 생략/포함 3가지 모두 중복을 허용 | 시각 정규화 뒤 중복 검사, 원본 CSV 행 안내, 422 뒤 기존 세션·결과 유지 |

| 고객사 간 점검자 ID 충돌 | 다른 고객 자료 추가 시 기존 고객의 점검자 이력 특징 변화 | `(site_id, inspector_id)` 집계, 같은 고객 내 여러 설비 이력은 공유 |
| 오래된 특징 캐시 | 예전 계산 의미의 캐시를 그대로 사용 | 특징 의미 버전과 학습 출처 기록, 오래된 캐시 재생성 |

새 점검이 들어오는 시각과 **이후 고장 기록이 완전하게 관측된 종료일**은 구별합니다. 모니터링은 최신 특징 시각까지 갱신하지만 점검 입력만으로 평가 종료일을 늘리지 않습니다. 관측 메타데이터가 있는 경우와 없는 경우 모두, 평가 가능 마지막 날짜와 평가 보류 상태가 유지되는지 검사합니다.

## 계산 상태의 의미

- 기본 60일 창은 데이터 로드/수집 시 갱신합니다. `/metrics` 수집 자체는 모델을 다시 실행하지 않습니다.
- `harbinger_drift_status`는 `not_initialized`, `success`, `insufficient_data`, `error`를 구분합니다. 부족/실패 상태의 경보 개수는 정상 0이 아니라 Prometheus `NaN`으로 표시합니다.
- 마지막 시도·마지막 성공 시각을 각각 제공합니다. JSON에는 계산할 수 없는 값이 `null`이며 결측률을 별도로 표시합니다.
- PSI는 창당 20행 미만이나 양쪽 전체 결측이면 평가를 보류합니다. 기존 0.10/0.25 기준은 진단용 관례적 임계값이며 고객 현장 최적값이라고 검증한 것은 아닙니다.
- `harbinger_p30`은 `latest_rows`를 거친 실제 관측자료의 점수 계산 건수입니다. 같은 자료의 반복 요청도 포함하고, 가상 변경·오프라인 평가·고유 설비 수와는 다릅니다.

## 기존 모델과 결과의 보존

원본과 수정 특징 생성기를 같은 축소 합성 자료에 적용했을 때 **1,401행 × 114열이 정확히 일치**했습니다. 합성 생성기의 점검자 ID는 이미 사이트별로 고유하기 때문입니다. 이 검사는 전체 고객 데이터의 일반화 성능을 입증하지 않습니다.

과거 학습 자료에서 고객사 간 점검자 ID가 겹쳤다면 특징 재생성과 재학습·재평가가 필요합니다. 현재 자료의 ID 검사만으로 출처가 다른 임의의 과거 모델 학습 방식을 증명할 수는 없습니다. 알려진 합성 번들과 외부 출처 모델을 구분해 검토해야 합니다.

기존 실험 수치·정적 예제·모델 버전은 덮어쓰지 않았습니다. [수정 전 release manifest](release-before.json)를 보존했고 현재 `artifacts/release.json`은 최신 소스와 기존 실험 산출물의 해시를 연결합니다. 소스 해시 갱신 자체는 모델 재학습을 뜻하지 않습니다. AWS 배포에서는 새 소스로 별도 런타임을 학습합니다.

## AWS 재배포에서 확인한 제한

[첫 재배포](https://github.com/sokldjs554/harbinger/actions/runs/40094279337)는 **실패**했습니다. 새 합성 런타임 `v20261024-125054` 학습은 완료했지만 `Remote.__init__`의 SSH 서버 신원 확인에서 중단되어 새 파일을 서버에 복사하지 못했습니다. [학습 출처](aws-attempt-1/deployment.json), [해당 런타임 지표](aws-attempt-1/metrics.json), [실패 범위](aws-attempt-1/result.json)는 성공한 배포 증거가 아닙니다.

[읽기 전용 진단](https://github.com/sokldjs554/harbinger/actions/runs/40096781696)에서 AWS 자격 증명으로 계정·인스턴스·보안 그룹·콘솔 조회가 성공했습니다. 최신 출력 65,535자와 기본 출력 65,369자 모두 SSH 공개키와 호스트 키 구간 표식이 없었습니다. [진단 원본](host-identity-diagnostics.json)에서 인스턴스 `i-0aaec13273afe3197`는 `running`, 임시 SSH 인바운드 규칙은 제거된 상태였습니다. 이 조회 자체는 공개 API의 현재 응답 상태를 검사한 것이 아닙니다.

재배포 코드는 명시적으로 등록한 **인스턴스 ID + Ed25519 공개키**를 사용하도록 보완했습니다. 형식·키 구조·ID 일치·콘솔과의 불일치를 검사하며, 누락되면 읽기 전용 사전 검사에서 중단합니다. 신원 검사를 끄거나 확인하지 않은 `ssh-keyscan` 결과를 신뢰하지 않습니다. 독립 검토와 배포 단위 테스트 32개를 통과했습니다. 이 보완 후 로컬 전체 테스트도 **136개 통과·선택적 TensorFlow 1개 제외**(102.35초)를 확인했습니다. [최종 로컬 로그](pytest-host-identity.txt). Ruff 검사·94개 파일 형식 검사·문서 수치·릴리스 해시 검사도 통과했습니다. 이 결과는 실제 SSH 접속 성공을 입증하지 않습니다.

**2026-10-25 해결:** 소유자가 AWS EC2 Instance Connect 관리 연결에서 공개키를 확인하고 `AWS_EC2_SSH_HOST_IDENTITY`를 등록했습니다. [재실행 attempt 2](https://github.com/sokldjs554/harbinger/actions/runs/40098079557/attempts/2)는 성공했으며, 소스 `e97a0a6c90a059dc549e453289416bf1d2be301b`와 새 합성 모델 `v20261024-152504`를 기존 서버에 반영했습니다. 실제 AWS 브라우저·CSV 계산·모바일, HTTPS·재부팅 복구·인증서 갱신 모의시험·SSH 규칙 제거까지 통과했습니다. [이번 배포 결과와 캡처](../aws-20261025/README.md)를 별도로 보존하며 위 실패 기록도 유지합니다. 이전 성공 실행에서 공개키를 검증했지만 실행기의 임시 파일에만 보존했던 문제는 등록된 서버 신원을 재사용하도록 보완했습니다.

AWS 콘솔 출력의 범위와 `Latest` 옵션은 [AWS API 문서](https://docs.aws.amazon.com/AWSEC2/latest/APIReference/API_GetConsoleOutput.html)와 [콘솔 출력 설명](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/troubleshoot-unreachable-instance.html)에서 확인했습니다. 실제 실패 판단은 위 실행 로그와 진단 결과를 근거로 합니다.
