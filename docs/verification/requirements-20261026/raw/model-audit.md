## Confirmed defects, fixes and reproduction evidence

1. **Double site dropout, medium training correctness impact.** Original `src/harbinger/models/deep.py:254` applied a permanent 30% mask when constructing training tensors, then lines 270–273 applied a second mask each epoch. Effective replacement probability was 1−(1−.3)^2=.51. The permanent subset never trained its own site's embedding. Instrumentation of the actual first `HazardNet.forward` training call measured 525/1024 zero-site inputs, exactly the union of the initial 313 and subsequent 303 sampled masks. Fix preserves original site IDs and only masks once per epoch. Regression records shuffled rows' actual forward inputs across two epochs and matches the configured random draws. The existing saved deep weights and their metrics are historical; this changes new training, not saved inference. No improved model score is inferred from this fix.

2. **Synthetic calendar duration fails across years/month ends, medium CLI correctness impact.** Original `src/harbinger/synth/generate.py:174–178` computed the destination year from months alone, ignoring the starting month. `generate(GenConfig(start=date(2024,11,1),months=3,scale=.01),verbose=False)` raised `ValueError: negative dimensions are not allowed`; start 2024-01-31/months1 raised `ValueError: day is out of range for month`. Longer durations crossing December could silently generate one year less than metadata claimed. Fix uses `pd.Timestamp(start)+pd.DateOffset(months=months)`, consistent with feature-cache observation-end semantics, and rejects nonpositive/noninteger/bool durations before generation. Actual generation tests verify November→January and January31→February28 inclusive (exclusive endpoint February29 in leap2024).

3. **Unequal C-index comparison cohorts, medium evaluation correctness impact.** Original `src/harbinger/eval/run.py:107–109` computes HGB C-index using only mature classification rows; original line200 copies it into the survival-model comparison, while Cox/AFT/deep use all test rows, including censored immature rows. Recomputing saved bundle `v20261021-103259` on its existing historical feature cache exactly reproduced the stored .7051560920181699 on 18,439 mature rows. On the common 22,001-row survival test cohort, the same HGB predictions give .7088412536398299. This is a denominator correction, not a new model-performance improvement. Fix adds `constant_hazard_metrics` and routes HGB survival evaluation through it, sharing one full cohort across C-index/IBS and emitting rows/cohort metadata. A three-row fixture produces1/3 rather than the mature-only1. Historical JSON remains unchanged.

4. **Generated survival-chart labels overstate experiment scope, medium evidence clarity impact.** Original `scripts/make_figures.py:288` labels `notext+site` as “메모 없음”, but `eval/run.py:214–219` passes the full numeric feature list (including `tx_*`) and only disables the character CNN. Original figure line301 says IBS30–360 days even though current `artifacts/survival.json` withholds360 and supports30/60/90/180. Fix labels the removed character CNN and retained numeric memo features explicitly. IBS labels derive from each model's actual `brier_at` keys; differing horizons are marked as not directly comparable. Figure tests render real PNGs and inspect the resulting axis labels. Existing historical image files were not regenerated by this worker.

5. **Nonphysical energy OLS expectations fabricate enormous features, high numerical correctness impact.** `features/energy.py` previously replaced every negative expected value with1e-6 before computing a residual ratio. A positive-only hand fixture produces an OLS prediction−50 and a fabricated ratio29,999,999. Fresh generated pytest tiny data confirms actual exposure: June S03 electricity forecasts reached−11232.1048 although measured electricity was at least20779.7; S01/S04 gas also had negative forecasts. This propagated huge standardized validation features into both Torch and TensorFlow, rather than indicating unusual real energy readings. Fix withholds nonpositive/nonfinite expected values as NaN. `FEATURE_SEMANTICS_VERSION` is now3 so old feature caches rebuild. Source fixture/outputs: `energy-reproduction.py/txt`, `energy-fresh-diagnostics.json`. New generated models must be reevaluated; no historical artifact was overwritten.

6. **Sparse energy training used a different window and invented site calibration, medium anomaly correctness impact.** `models/energy.py` computed sigma from7 readings with minimum4, while inference uses7 calendar days with minimum3. Forty weekly observations yielded a stored positive sigma .01014530590113635 despite zero eligible7-day windows. Fix uses the same calendar window/minimum as inference and omits site sigma when there are not more than10 eligible windows or sigma is nonpositive/nonfinite. No global residual fallback is substituted. A mixed daily/weekly fixture verifies exact daily sigma and that later dense observations for the unsupported weekly-trained site retain `no_model` status. Both energy regressions failed before and passed after (`energy-regressions-red.txt`, `energy-regressions-green.txt`).

Reproduce pre-fix observations with `model-reproductions.py` and inspect saved `model-reproductions.json` in this directory. `model-artifact-check.py/json` provide the saved-bundle same-cohort correction. These scripts read source/current code when rerun, so the saved original output, not a later rerun, records pre-fix behavior.

## Boundary and methodological findings

Confirmed present in real code:
- Feature work-order windows use strictly `opened_at<t`; labels use `(t,t+30d]` and explicit observation end. `observe_until` masks immature y30 and censors both survival time and event. Tests cover exact cutoff events and future-record invariance.
- Energy feature residuals fit previous calendar months with a frozen `fit_until`, require60 past observations, and rolling features exclude the current day. They are separate from the HGB electricity regressor.
- Inspector history is grouped by site+inspector, whereas asset IDs are expected globally unique; corresponding cross-site isolation tests exist.
- HGB classification, logistic baseline, Cox PH, Weibull AFT, PyTorch character-CNN discrete hazard model, optional missing-aware CNN, and HGB electricity regression are implemented. Model types are not merely prose.
- Calibration selects raw/Platt/isotonic with cross-fit validation logloss; no test labels enter that selection. Sparse one-class folds withhold calibration. Random within-validation folds do not constitute independent temporal or site generalization validation.
- HGB text ablation removes memo-derived quality and weighted-checklist features as well as tx features; the deep no-CNN variant deliberately keeps numeric features and must be named accordingly.
- LOSO excludes held-site labels from classifier training and calibration, excludes energy features, and applies own-label maturity cutoffs. Only selected sites are held out (not all sites); cold-start offset uses number of events for shrinkage, so no events means zero offset even with long negative history. This is a design limitation, not a hidden result.
- Site-policy selection uses four or more fixed30-day snapshots spanning90days, mature complete outcome assertions, minimum50 assets and both outcome classes per snapshot, paired top10/Brier criteria, bootstrap sensitivity gates, content hashes, a future reserved test boundary, atomic revision transitions and baseline rollback. The saved audit policy retains baseline on all five sites; it is not empirical proof that customer-specific models improve performance. Complete outcome ascertainment remains an operator assertion. Policy hashes are integrity checks inside the trusted administrator model directory, not signatures.
- Signal tables use contributing-site bootstrap for pooled row-weighted descriptive rates and withhold empty/single-outcome/too-few-site confidence intervals. They explicitly combine train/validation/test descriptively and should not be called held-out model performance.
- Patrol simulation ranks pure model risk with common site/date budgets; production prescription also adds importance and mandatory legal-demo constraints, so their results are different policies.

Unfixed limitations / issues requiring separate scope or a stated statistical convention:
- `prescribe/schedule.py:43–46` rounds and clips intervals to a minimum7days. For P30=.4 and budget.05, raw interval≈3.0days becomes7 and implied constant-hazard risk is .11236321498279656, not≤.05. The implementation and tests intentionally enforce the minimum; documentation/API should distinguish constrained recommendation from a guaranteed budget. `urgent=True` is present. No unauthorized schedule change was made.
- **IPCW disposition: not a confirmed defect; no code change.** `eval/metrics.py:55–63` uses right-continuous censoring KM at observed event times. A tied-censor/event example yields.333333 instead of.25 under a left-limit event-weight convention, but that hand example only demonstrates a convention difference. External reference retrieval was blocked/aborted; this audit did not establish that the current convention violates its standard. Do not call all IPCW edge cases fixed, and do not claim demonstrated impact on the continuous-time historical sample. A fully specified tie/censoring estimator convention and reference comparison remain a methodological follow-up.
- Training-derived censoring KM is applied to a test interval with much shorter administrative follow-up. IPCW comparability requires assumptions about censoring; very late test-horizon scores merit a sensitivity analysis. This audit does not establish their bias magnitude.
- Patrol bootstrap samples equal-weight site means while the point precision is site-day weighted. For the existing balanced25×18 artifact these coincide; irregular site coverage needs a matching estimand.
- The latent-state “oracle” computes a frozen-state hazard approximation, ignoring future degradation, interventions and downtime. It is not a mathematically guaranteed upper bound or a true counterfactual30-day probability. Synthetic generation deliberately embeds associations between deterioration, memos and outcomes; predictive success does not validate them in customer data.
- These checks do not establish external customer benefit, real facility safety/legal compliance, or hiring qualifications such as education/years of experience. Legal intervals are demo assumptions.
