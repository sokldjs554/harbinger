# 기록 조건과 학습 시드를 바꿔 다시 확인한 방법

실험 조건은 실행 전 [설계](../../superpowers/specs/2026-10-25-robustness-design.md)에 고정했습니다. 이 문서는 합성 모델의 오프라인 평가이며 실제 사용자 검토나 고객 현장 실증 결과가 아닙니다.

## 같은 조건에서 비교하기

생성 시드 20260101·20260102·20260103 각각에 학습 시드 17·29를 적용합니다. 각 생성 세계는 36개월, scale=1이며 시간 순서로 24개월 학습·6개월 검증·6개월 테스트를 나눕니다. 학습과 검증 끝의 30일 정답이 성숙하지 않은 행은 분류 학습·보정에서 제외합니다. 생존 모델은 경계에서 관측을 중도절단합니다.

HGB, 로지스틱, 메모와 파생 특징을 제거한 HGB, 최근 점검 특징만 사용하는 HGB, PyTorch text+site 생존 모델을 비교합니다. PyTorch는 최대 40 epoch, 기존 검증 손실 조기종료를 그대로 사용합니다. 주간 선택에서는 최근 점검 판정 규칙도 함께 비교합니다. 모델 구조·하이퍼파라미터를 테스트 결과에 맞춰 바꾸지 않습니다.

점검 행의 예측과 매주 월요일의 설비 선택은 서로 다른 평가 단위입니다. 주간 평가는 동일 기준일·설비·이후 30일 고장 정답과 사이트당 최대 10개 선택 예산을 사용합니다. 7개 입력 조건 모두에서 사용할 수 있는 설비의 교집합을 사용하고, 조건별 가용 수와 공통 수를 저장합니다.

## 기록이 불완전할 때

검증 종료 후의 점검에만 메모 손상을 적용하고 깨끗한 데이터에서 학습한 모델을 고정해 평가합니다.

| 조건 | 조작 | 해석 범위 |
|---|---|---|
| 메모 누락 | 점검 행의 25%·50%를 결정론적으로 빈 문자열 처리 | 임의 누락에 대한 민감도 |
| 문자 손상 | 공백 외 문자의 10%·30%를 결정론적으로 삭제 | 일부 오타 상황의 대리 실험; 치환·전치 등 모든 오타를 대표하지 않음 |
| 점검 기록 지연 | 기준일보다 3일·7일 이전에 작성된 점검까지만 사용 | 점검 기록에 동일한 도착 지연 적용; 정비 기록은 즉시 도착한다고 가정 |

메모 특징, 메모에서 파생된 이력·품질 특징을 다시 계산합니다. 에너지 특징은 원본을 유지하며, 과거 입력과 정답이 변하지 않았는지 확인합니다. 메모를 제거한 모델의 예측이 메모 손상 조건에서 동일한지도 검사합니다.

지연 조건은 과거 점검의 입력을 기준일로 갱신하며, 미래 점검 원문을 읽지 않습니다. 정답은 원본 고장 기록으로 기준일 이후 30일에서 다시 계산합니다. 지연과 무관한 동일 정답·공통 모집단으로 비교하므로 오래된 점검의 정답을 대신 평가하지 않습니다.

## 확률 보정 검증의 중복을 줄이기

검증 기간의 HGB 원시 확률에서 네 가지 분할을 비교합니다.

1. 행 단위 무작위 5-fold: 기존 방식과 비교하는 기준입니다.
2. 설비 단위 GroupKFold: 같은 사이트·설비가 보정 적합과 검증 양쪽에 들어가지 않습니다.
3. 시간 순서 분할: 앞의 기간에서 적합하고 뒤의 기간에서 검증합니다. 적합 행의 `점검 시각 + 30일`이 검증 시작보다 엄격히 이전이어야 합니다.
4. 시간 순서+설비 제외: 3번 조건에 더해 검증 설비의 행을 보정 적합에서 제외합니다.

모든 방식에서 유효한 OOF 예측을 얻은 **공통 검증 행**으로 원시 확률·Platt·isotonic의 logloss를 비교합니다. 원시 확률 대비 0.5%를 넘는 상대 개선이 있어야 보정을 채택합니다. 초기 준비 기간, 빈 적합 집합, 단일 클래스 적합은 보류합니다. 방법 선택을 저장한 뒤 전체 성숙 검증 행에 보정기를 다시 적합하고 테스트를 평가합니다. 테스트 정답은 보정 방법 선택에 전달되지 않습니다.

설비 분리는 **보정기 적합 자료**에 적용됩니다. 기본 예측 모델은 앞선 학습 기간에서 해당 설비를 봤을 수 있으므로 이 실험을 처음 보는 고객사 일반화 검증이라고 표현하지 않습니다. 단일 검증 기간에서의 조기종료와 기존 모델 학습 절차도 유지합니다.

## 범위와 불확실성

- 6회는 서로 독립인 세계 6개가 아니라 **3개 생성 세계 안에서 2회씩 학습한 중첩 실험**입니다. 세계별 평균을 먼저 구하며 최솟값·최댓값은 기술 통계입니다.
- 주간 Precision@10 차이는 같은 사이트를 함께 재표집하는 paired site bootstrap 2,000회로 계산합니다. 반복 설비·주간 관측은 사이트 안에서 함께 묶습니다. 구간은 해당 합성 세계와 학습 결과에 조건부이며 실제 고객 모집단의 신뢰구간이 아닙니다.
- ECE는 bin에 의존하고, 이 실험의 분류 지표는 30일 내 고장 여부에 대한 것입니다. 비용 절감, 사고 방지, 현장 효과를 직접 검증하지 않습니다.
- 입력 손상의 정도는 실험 조건이며 실제 현장의 누락률·오타율·지연 분포를 추정한 값이 아닙니다.
- 합성 데이터 생성기의 관계를 얼마나 학습했는지 확인하는 실험입니다. 실데이터의 분포 변화와 업무 적합성은 별도로 검증해야 합니다.

## 다시 실행하기

Python 환경과 의존성 설치는 [개발자 실행 안내](../../running.md)를 사용합니다. 기존 결과를 덮어쓰지 않도록 새 출력 경로를 지정합니다. CPU 스레드를 고정합니다.

```bash
for seed in 20260101 20260102 20260103; do
  PYTHONPATH=.:src OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
    python -m scripts.robustness.run --data-seed "$seed" \
    --work /tmp/harbinger-robustness --out /tmp/harbinger-robustness-results
done
PYTHONPATH=.:src python -m scripts.robustness.summarize /tmp/harbinger-robustness-results
```

`--smoke`는 축소 데이터와 2 epoch로 실행 경로만 확인합니다. 전체 결과를 대신하지 않습니다. 전체 실행에는 원자료·특징·학습 중간 상태를 위한 메모리와 시간이 필요합니다. 이 검사는 외부 유료 API를 호출하지 않습니다.

`results/data-*/provenance.json`에는 실행 코드, 소스 해시, 데이터 출처·해시, 패키지 버전, 분할, 실제 손상량과 가용 모집단을 남깁니다. `model-*/calibration-selection.json`은 테스트 평가 전 선택 기록입니다. 압축 CSV·NPZ에는 행 정체성, 정답, 예측, 보정 fold, OOF 예측과 공통 마스크를 저장합니다. `sha256.json`과 검증 스크립트로 해시·지표·시점 가용성·설비 분리·30일 purge를 재검사합니다.
