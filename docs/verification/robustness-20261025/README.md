6회는 **3개 생성 세계 안에서 2회씩 학습한 중첩 실험**입니다. 아래 평균은 세계별 평균을 다시 평균한 값이며, 범위는 6회 최솟값–최댓값입니다. 범위를 신뢰구간으로 해석하지 않습니다. README의 기존 단일 실행 수치와는 학습 시드 및 주간 평가 날짜 구성이 다릅니다.

## 기록 누락과 지연의 영향을 따로 확인했습니다

아래는 깨끗한 입력 대비 **HGB 주간 Precision@10 변화**입니다. 단위 pp는 퍼센트포인트입니다. 예를 들어 −1 pp는 25%에서 24%로 낮아진 것입니다.

| 조건 | 평균 변화 (pp) | 실행별 변화 범위 (pp) | AUROC 평균 변화 | 사이트 bootstrap 95% 구간이 0 아래인 실행 |
|---|---:|---:|---:|---:|
| 메모 누락 25% | -0.361 | -1.236–+0.109 | -0.0032 | 1/6 |
| 메모 누락 50% | -1.042 | -1.800–-0.382 | -0.0087 | 5/6 |
| 문자 삭제 10% | -0.258 | -0.800–+0.091 | -0.0017 | 1/6 |
| 문자 삭제 30% | -1.006 | -2.000–+0.145 | -0.0076 | 4/6 |
| 기록 지연 3일 | -0.033 | -0.255–+0.509 | -0.0025 | 0/6 |
| 기록 지연 7일 | -0.045 | -0.545–+0.436 | -0.0047 | 1/6 |

구간은 사이트를 묶어 재표집한 2,000회 paired bootstrap입니다. 반복 설비와 겹치는 주간 관측을 사이트 안에 함께 유지합니다. 각 구간은 해당 합성 세계에 조건부이며, 6회 전체에 대한 공동 유의성이나 실제 고객 효과의 근거가 아닙니다.

다른 모델도 같은 손상 조건으로 평가했습니다. 아래 값은 각 모델의 깨끗한 입력 대비 주간 Precision@10 평균 변화(pp)입니다.

| 조건 | HGB 전체 | 메모 제외 HGB | 로지스틱 | 최근 점검 특징 HGB | PyTorch |
|---|---:|---:|---:|---:|---:|
| 메모 누락 25% | -0.361 | +0.000 | -0.236 | +0.000 | -6.209 |
| 메모 누락 50% | -1.042 | +0.000 | -0.721 | +0.000 | -6.167 |
| 문자 삭제 10% | -0.258 | +0.000 | +0.000 | +0.000 | -0.555 |
| 문자 삭제 30% | -1.006 | +0.000 | -0.273 | +0.000 | -2.379 |
| 기록 지연 3일 | -0.033 | -0.333 | -0.206 | -0.803 | -0.415 |
| 기록 지연 7일 | -0.045 | -0.567 | -0.424 | -1.770 | -0.924 |

**추가 보완이 가장 필요한 부분은 PyTorch의 메모 누락 대응입니다.** 메모 누락 25%에서 주간 Precision@10은 평균 23.94%에서 17.73%로, 약 6.21 pp 낮아졌습니다. 같은 조건의 HGB 감소는 약 0.36 pp였습니다. 누락률과 선택 성능은 모든 실행에서 단조 관계가 아니므로 50% 조건도 그대로 공개했습니다. 누락 메모를 포함한 학습, 누락 표시, 메모를 사용하지 않는 모델로의 전환은 후속 비교 후보이며, 개선 효과는 아직 검증하지 않았습니다. 후속 방법은 이 테스트 결과에 맞춰 고르지 않고 새로운 검증·테스트 계획으로 평가해야 합니다. 이후 새 합성 세계에서 실행한 결과는 [메모 누락 대응 후속 실험](../memo-20261025/README.md)에 별도로 기록했습니다. 위 수치는 당시 결과로 보존합니다.

메모를 쓰지 않는 모델의 메모 손상 예측이 완전히 동일한지 원시 배열로 검사했습니다. 문자 삭제는 오타의 일부 상황만 흉내 냅니다. 3일·7일 지연은 점검 기록에 일률적으로 적용했고 정비 기록은 즉시 도착한다고 가정했습니다. 변화가 작거나 양수인 실행이 있어도 기록 지연이 유익하다는 의미는 아닙니다.

## 보정은 개선 근거가 있을 때만 선택했습니다

각 방식의 유효 OOF 예측이 모두 존재하는 공통 검증 행에서 선택했습니다. 원시 확률 대비 검증 logloss가 0.5%를 넘게 개선돼야 Platt 또는 isotonic을 채택합니다. 방법 선택을 저장한 뒤 테스트를 평가했습니다.

| 검증 분할 | 원시 확률 / Platt / isotonic 채택 횟수 | OOF logloss 평균: 원시 / Platt / isotonic ↓ | 테스트 Brier 평균 ↓ |
|---|---:|---:|---:|
| 행 무작위 | 5 / 1 / 0 | 0.24373 / 0.24304 / 0.24515 | 0.06885 |
| 설비 분리 | 5 / 1 / 0 | 0.24373 / 0.24308 / 0.24496 | 0.06885 |
| 시간 순서 + 30일 간격 | 5 / 1 / 0 | 0.24373 / 0.24352 / 0.24971 | 0.06885 |
| 시간 순서 + 30일 간격 + 설비 제외 | 5 / 1 / 0 | 0.24373 / 0.24365 / 0.25247 | 0.06885 |

네 분할 방식은 이번 6회에서 같은 방법을 선택했습니다: 원시 확률 5회, Platt 1회, isotonic 0회입니다. Platt를 선택한 생성 20260103 / 학습 17에서 테스트 Brier는 원시 0.071149 → 보정 0.071020, logloss는 0.256386 → 0.254794, ECE는 0.015412 → 0.004933이었습니다. 이 한 조건의 개선을 모든 고객에게 보정이 필요하다는 근거로 사용하지 않습니다.

설비 제외는 보정기 적합에 적용한 조건입니다. 기본 예측 모델이 학습 기간에 해당 설비를 전혀 보지 않았다는 뜻은 아닙니다. 원시 확률을 선택한 실행은 테스트에서도 그 확률을 사용하므로, 분할 방식이 달라도 테스트 값이 같을 수 있습니다. 분할을 엄격하게 했다는 이유만으로 보정 성능이 개선됐다고 주장하지 않습니다.

## 고객별 선택은 이 근거 위에서 이어갑니다

현재 단계에서 만들 수 있는 것은 **선택 기준과 비교 절차**입니다. 특정 실제 고객에게 가장 적합한 모델을 정했다는 근거는 아직 없습니다.

1. 고객 자료의 시각·설비 ID·누락·관측 종료를 확인하고, 같은 미래 기간과 점검 예산으로 평가 대상을 고정합니다.
2. 전체 HGB·메모 제외 HGB·단순 기준을 시간 분리 검증에서 비교합니다. 점검 우선순위에는 Precision@10과 고객의 실제 점검 비용을, 확률 사용에는 Brier·logloss를 함께 봅니다.
3. 보정은 반복 설비와 관측 기간 중복을 고려해 검증하고, 개선 근거가 부족하면 보류합니다. 결과가 불안정하거나 고장 관측이 부족하면 고객별 우열을 확정하지 않습니다.
4. 친구·동료의 검토로 화면 이해와 작업 흐름을 개선합니다. 관련 경험자의 의견과 실제 고객 데이터 성능은 구분해 기록합니다. 사용자 의견만으로 예측 모델의 성능 우열을 결정하지 않습니다.

사용성 검토와 이번 평가는 병행할 수 있습니다. 실제 검토 기록을 받은 뒤 **관찰된 문제 → 수정·재검토 → 평가 안정성 근거 → 고객별 선택 기준**을 포트폴리오에서 연결합니다. 실제 고객 PoC 완료 주장은 별도 현장 자료와 평가가 있어야 가능합니다.
