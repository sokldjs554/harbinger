# 독립 코드 검토와 수정

실행 작업자와 별도의 검토자가 변경 코드·계획·검증을 읽었다. Critical 0, Important 1, Minor 1. 검토자가 실행한 분석/업로드 테스트 20개 통과.

## Important — 자료 전환 후 이전 확인이 남음

`populateControls`가 관측 종료일을 프로그램으로 바꾸면 input/change 이벤트가 발생하지 않았다. 확인한 CSV 뒤 합성 예제로 전환할 때 이전 파일·체크가 다른 날짜와 결합될 수 있었다. `check_review_usability`에 해당 전환 순서를 추가해 체크가 남는 실패를 확인했다. 자료 활성화 시 확인을 해제한 뒤 실제 API 전체 브라우저 검사와 전체 Python 테스트를 다시 통과했다.

## Minor — 입력 명세의 숫자 오류 범위

기본 숫자 5개 열만 한국어·행 번호로 안내하는데 문서가 모든 숫자 오류처럼 표현했다. 문서 범위를 기본 5개 열로 명확히 하고 선택 chk_* 항목은 기존 열 이름·허용값 안내임을 명시했다. 새 체크리스트 오류 UI 기능은 추가하지 않았다.

## 검토 범위의 구분

참가자가 실제로 한 행동·시간 측정은 코드 검토자가 검증하지 않았다. 모델 성능 개선은 이번 수정 대상이 아니다. 전체 브라우저·CI·공개 배포 검증은 작업자가 별도 실행한다. 참가자 재검토를 자동 브라우저 검사로 대체하지 않는다.

## 구현 판단

- 기록 완전성을 모르는 경우 업로드를 막는 대신 탐색을 허용하고 서버 평가를 보류했다. 모델을 바꾸지 않아도 확인되지 않은 정답을 성능으로 해석하지 않는다.
- 저장 예제 위치는 확인되는 상세 응답만 사용했다. 일부 설비는 위치 검색에서 제외되는 제한을 공개했다.
- Playwright 최신 설치의 Chromium 다운로드가 유효한 ZIP을 반환하지 않아 실제 설치·검증된 1.56.0으로 브라우저 검증 버전을 고정했다.
- 자료 전환 시 확인란을 항상 해제한다. 같은 파일을 다시 분석할 때 다시 확인해야 하는 비용보다 다른 날짜로 확인이 넘어가는 위험을 줄이는 것이 우선이다.
