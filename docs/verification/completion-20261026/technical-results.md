# 평가 보완 1–4의 확인 결과

2026-10-26. [사전 작업 계약](../../superpowers/specs/2026-10-26-evaluation-completion.md)에 따른 기술 결과다. 메모 누락 재실행은 기존 세계의 수정 후 반복이고, HGB 기본 모델 선택은 새로 고정한 생성 시드의 검증 구간을 사용했다. 순찰 평가는 과거 합성 세계와 고정 모델의 선택·집계 구현을 대조했다. 세 결과의 자료·목적을 서로 바꾸어 성능 근거로 사용하지 않는다.

**HGB 기본값은 전체 특징 모델(`full`) 유지로 결정됐다.** 메모 제외 후보의 교체 조건이 검증 구간에서 충족되지 않았으며, 선택과 검증 예측 해시를 고정한 뒤 여섯 테스트 실행을 계산했다. 과거 메모 누락 결과나 이미 공개한 단일 세계 테스트로 기본값을 선택하지 않았다.

이 문서는 기술 항목 1–4의 확인된 근거만 다룬다. 후속 처리량 비교, 최종 전체 검사·CI·병합·AWS/Pages 배포의 완료 여부와 최종 실행 소스/모델/특징 버전은 별도 완료 기록으로 확인해야 한다. 아래 재실행·재생 실험의 버전을 현재 공개 서비스 버전으로 간주하지 않는다.

## 1. 수정 후 메모 누락 재실행

소스를 `5a7f947146dd24b43eb79a8e4744449615dabc17`로 고정하고 자료 시드 202610251/252/253 × 학습 시드 17/29를 그대로 실행했다. scale 1, 36개월, 24/6/6 시간 분할, 최대 40 epoch·patience 6·lr .002·batch 1024, clean/25/50/100% 누락, 세 모델과 검증 선택·최종 판정 기준을 변경하지 않았다. 100% 누락은 극단 조건 보고용이다.

특징 정의는 v3이며 고객사 ID 가리기는 과거의 최초 30% 고정 마스크와 epoch별 30% 마스크를 합친 기대 51%에서, epoch마다 한 번 새로 뽑는 30%로 수정됐다. 개선형의 **메모 dropout 35%**는 별도 설정이다. 소스 변경 전체의 재실행이므로 지표 차이를 특정 수정 하나의 인과 효과로 분해하지 않는다.

| 검증으로 선택한 정책의 테스트 지표 | 과거 | 수정 후 |
|---|---:|---:|
| 같은 실행의 legacy 대비 25/50% 누락 평균 향상 | +5.297%p | +5.100%p |
| 같은 실행의 legacy 대비 정상 입력 평균 변화 | +0.170%p | +0.139%p |
| 정상 입력 평균 Brier / legacy 평균 Brier | 1.005906 | 1.004797 |
| 원래 고정한 최종 판정 | 통과 | 통과 |

여섯 선택은 세계·학습 시드 순서로 `no_memo, no_memo, robust, no_memo, robust, legacy`였다. 세 세계의 실행은 각각 약 22.6/22.8/23.2분에 종료 코드 0으로 끝났고, 원래 `memo_summary` 및 원시 비교 재검증도 통과했다. 원자료 21개 파일의 해시, 평가 대상·정답·손상 수가 과거와 일치하며 과거 증거 118개 파일을 보존했다.

[전체 보고서](memo/report.md), [여섯 실행·조건별 지표와 판정](memo/results/summary.json), [720개 검증/테스트 지표 전후 비교](memo/all-runs-metrics-comparison.csv), [평균](memo/mean-metrics-comparison.csv), [표준편차·최솟값·최댓값](memo/dispersion-comparison.csv), [패키지 검증](memo/package-verification.json)에 수치와 근거가 있다. [원래 결과](../memo-20261025/README.md)는 소급 수정하지 않았다. 같은 세 세계 안의 두 학습 반복을 독립 세계 여섯 개로 세지 않으며, 알려진 시드의 반복을 새 독립 성능 입증으로 표현하지 않는다.

## 2. HGB 기본 모델의 새 검증 선택

자료 시드 **202610261/262/263** × 학습 시드 **17/29**, scale 1·36개월·24/6/6 분할에서 전체 특징 116개와 메모 유래 특징을 제외한 84개를 비교했다. 새 생성 시드는 같은 생성기의 미관찰 세계이며 실제 신규 고객 자료가 아니다. 보정과 후보 선택이 같은 검증 기간을 사용했으므로 검증 점수를 독립 테스트 점수로 부르지 않는다.

교체 조건은 검증 여섯 실행 모두 Precision@10 비감소·Brier 비증가, 평균 AUROC·PR-AUC 비감소, 고객사 블록 paired bootstrap 2,000회의 평균 Precision@10 차이 하한 > 0이었다. 세계별로 고객사를 재표집하고 같은 재표집을 두 학습 시드에 공유했으며 세계·학습 실행은 같은 가중으로 평균했다. 세부 문턱은 구현자가 결과 확인 전에 정한 것이며 사용자가 지정한 수치인 것처럼 표현하지 않는다.

메모 제외 후보는 검증 여섯 실행에서 모두 Precision@10가 낮고 Brier가 높았다. 평균 AUROC·PR-AUC도 낮았으며, `no_memo − full` Precision@10의 조건부 95% 구간은 **−0.7715~+0.1556%p**였다. 따라서 `full`을 유지했다. 이는 메모의 보편적 우월성이나 실제 고객 일반화를 입증하지 않는다.

| 구간 | 모델 | Precision@10 평균 | AUROC 평균 | PR-AUC 평균 | Brier 평균 |
|---|---|---:|---:|---:|---:|
| 검증 | full | 26.5905% | 0.775416 | 0.262269 | 0.064983 |
| 검증 | no_memo | 26.2667% | 0.770463 | 0.260270 | 0.065224 |
| 동결 후 테스트 | full | 25.8909% | 0.772578 | 0.257555 | 0.066285 |
| 동결 후 테스트 | no_memo | 25.5212% | 0.767690 | 0.255462 | 0.066442 |

| 세계 / 학습 시드 | 검증 full P@10 | 검증 no_memo P@10 | 테스트 full P@10 | 테스트 no_memo P@10 |
|---|---:|---:|---:|---:|
| 202610261 / 17 | 27.8476% | 27.7905% | 26.0909% | 26.5636% |
| 202610261 / 29 | 27.3905% | 27.3524% | 26.1455% | 26.3091% |
| 202610262 / 17 | 26.2476% | 25.6762% | 26.3818% | 24.9818% |
| 202610262 / 29 | 26.0952% | 26.0571% | 25.6182% | 25.1273% |
| 202610263 / 17 | 25.7143% | 25.2000% | 25.4000% | 24.8000% |
| 202610263 / 29 | 26.2476% | 25.5238% | 25.7091% | 25.3455% |

테스트에서는 첫 세계의 두 학습 실행에서 메모 제외 P@10가 더 높았지만, 이 결과로 선택을 되돌리거나 문턱을 조정하지 않았다. 평균만 제시하지 않고 [summary의 `runs`·`means`·`dispersion`](default/summary.json)에 두 구간의 모든 실행, AUROC·PR-AUC·Brier·P@10 평균과 표준편차·범위를 함께 남겼다. 반복 간 편차는 기술통계이며 독립 세계 여섯 개의 불확실성이 아니다. AUROC·PR-AUC·Brier는 평가 스냅샷 행 기준이고 P@10는 고객사별 날짜 평균을 낸 뒤 고객사를 같은 가중으로 평균한다.

[선택 및 실패한 교체 조건](default/selection.json), [테스트 전 동결 해시](default/freeze.json), [원시 예측·정답·실행 기록](default/)으로 선택 순서를 확인할 수 있다. 요약의 `recomputed_all_scores=true`, `selection_unchanged=true`를 확인했다. 각 세계 provenance의 소스 커밋·파일 해시를 사용하며 최종 배포 소스 버전은 이 기록으로 추정하지 않는다.

## 3. 확률 순위와 실제 순찰 선택 분리

[공동 선택 함수](../../../src/harbinger/prescribe/priority.py)의 `select_patrol`을 서비스와 평가가 함께 사용한다. 확률 모델은 확률 × 중요도 가중(1/1.8/3), 규칙 비교군은 각 규칙의 우선순위를 사용한다. 모두 같은 설비·날짜·요청 K·필수 설비 조건을 공유한다. 필수 수가 K를 넘으면 모두 포함하고 실제 선택 수·필수 수·초과량·적중 수를 남긴다. 이 선택의 적중률을 Precision@10라고 부르지 않는다.

아래는 기존 합성 세계 seed 20260101, 저장 모델 `v20261026-074224`의 **재생 평가**다. 이 버전은 해당 근거의 입력 모델이며 최종 재학습/공개 서비스 버전이라는 뜻이 아니다. 학습 이후에도 이전 점검 이력을 가용 후보로 포함한 `full_history_service_window`에서 25개 고객사 × 18개 성숙 날짜를 비교했다.

| 방식 | 전체 HGB | 최근 점검 판정 규칙 | 메모 제외 HGB |
|---|---:|---:|---:|
| 확률/규칙 순위 상위 10개 P@10 | 23.8444% | 12.2000% | 24.9556% |
| 필수 포함·중요도 적용 실제 선택 적중률 | 20.3111% | 11.1778% | 20.5111% |

실제 HGB 선택은 4,500회 선택 중 914회 적중, 필수 선택 613회, K 초과 0회였다. 고객사 동일 가중 적중률의 조건부 95% 구간은 **17.5556~23.0444%**이고 최근 점검 규칙과의 차이는 **+9.1333%p**, paired 구간은 **+7.2222~+11.0450%p**였다. 이번 합성 재생 자료에서 초과가 0이라는 사실을 필수 수>K 코드 경계의 검증으로 대체하지 않는다. 해당 경계는 [선택·집계 회귀 검사](../../../tests/test_service_patrol_evaluation.py)에서 별도로 다룬다.

서비스와 평가가 같은 대상과 필수 조건으로 같은 선택을 내는지 3개 고객사 × 3개 날짜 표본 9개에서 확인했다. 이를 모든 운영 입력의 동등성이나 공개 API 부하 시험으로 확대하지 않는다. 과거 데이터/모델 파일은 변경하지 않았다. [모든 방법·시나리오·고객사 구간·대상 이력](patrol/actual/summary.json), [선택 멤버십 원본](patrol/actual/full_history_service_window.json.gz), [파이프라인 검사](../../../tests/test_patrol_pipeline_integration.py)를 함께 확인한다. 과거 단일 세계에서 메모 제외 모델이 높았다는 사실은 항목 2의 새 검증 선택을 대신하지 않는다.

## 4. 지표와 bootstrap의 고객사 가중 일치

주 순찰 지표는 **고객사 안에서 날짜별 적중률 평균 → 고객사 평균**이다. bootstrap도 같은 고객사 평균을 재표집하고 한 고객사의 반복 설비·겹친 기간을 함께 유지한다. 비교 방식의 공통 고객사·날짜와 완전한 쌍을 요구하며 빈 자료·불완전 쌍·한 고객사처럼 근거가 부족하면 불확실성 추정을 보류한다. 과거 날짜 가중 지표는 `historical_date_weighted_*`로 별도 보존한다.

| 자료와 HGB 지표 | 과거 날짜 가중 | 고객사 동일 가중 |
|---|---:|---:|
| 균등한 25개 고객사 × 18일, 과거 후보 P@10 | 23.8222% | 23.8222% |
| 불균등 날짜 253개 고객사·날짜 쌍, P@10 | 24.8617% | 23.9422% |
| 같은 불균등 날짜, 실제 순찰 선택 적중률 | 20.9881% | 20.3289% |
| 두 고객사 불균등 날짜 진단 fixture | 25% | 50% |

균등 자료에서는 두 추정값이 일치하고 날짜 수가 다른 자료에서는 달라진다. 불균등 날짜 제한은 집계 구현을 확인하기 위한 결정적 진단이며 새 성능 평가 모집단이 아니다. [진단 fixture](patrol/estimator-demonstration.json), [시나리오별 독립 재계산과 구간](patrol/actual/summary.json)의 `estimator_checks`·`site_date_counts`에 근거가 있다. 구간은 고정 모델과 해당 합성 고객사에 조건부이며 실제 고객 신뢰구간으로 해석하지 않는다.

항목 1의 기존 메모 실험은 원래부터 선택 적중 수의 합/선택 수의 합을 점 추정과 고객사 bootstrap 양쪽에서 재계산했다. 그 과거 계약을 이번 고객사 동일 가중 지표로 소급 변경하지 않았다.

## 증거 사용 범위와 남은 확인

[공고 대응표](../../job-requirements-audit.md)와 [제출 전 근거 인계](../../submission-evidence-20261026.md)는 위 수치·선택 이유·한계를 연결한다. 실험을 수행한 사실과 사용자 개인의 단독 코딩 능력·학력·고용 경력·현장 성과는 별개다. 처리량·최종 로컬 검사·버전 및 CI/배포 실행 링크는 [완료 검증 기록](README.md)에 연결한다. 기존 검증 문서의 과거 통과 기록을 이번 최종 검증 완료로 옮겨 적지 않는다.
